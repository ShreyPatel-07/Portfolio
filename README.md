# Shrey Patel — Portfolio

A cinematic, editorial portfolio built to do two jobs: make a strong first impression, and let a
recruiter or hiring manager verify the work in under a minute.

**Stack:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · GSAP + ScrollTrigger ·
Motion · Three.js / React Three Fiber · Lenis · Lucide.

---

## Run it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm start          # serve the production build
npm run typecheck  # tsc --noEmit
npm run resume     # regenerate public/Shrey-Patel-Resume.pdf
```

Optional: set `NEXT_PUBLIC_SITE_URL` (e.g. `https://yourdomain.com`) so canonical URLs, the
sitemap and Open Graph metadata point at the real domain. Without it the site falls back to
`http://localhost:3000`.

## Where the content lives

Everything is centralised. No copy is hardcoded inside section components.

| File | Controls |
| --- | --- |
| `src/content/profile.ts` | Name, role, positioning, bio, stats, facts, contact details, résumé path |
| `src/content/projects.ts` | **All projects** — featured rail, archive and case-study pages |
| `src/content/experience.ts` | Roles, contributions, stacks, education |
| `src/content/skills.ts` | Capability groups and tiers (`core` / `working` / `familiar`) |
| `src/content/process.ts` | The six-step working method and its evidence |
| `src/content/credentials.ts` | Certifications, archive thumbnails, achievements |
| `src/content/nav.ts` | Section navigation + capability marquee |

### Adding a project

1. Append an entry to `projects` in `src/content/projects.ts`.
2. Set `featured: true` to put it in the horizontal showcase, or `false` for the archive.
3. Add a visual:
   - **Real capture:** drop the image in `public/work/`, then set
     `visual: { hasScreenshot: true, src: "/work/your-shot.png", alt: "…" }`.
   - **No capture yet:** keep `hasScreenshot: false`. The site draws an art-directed placeholder
     plate and labels it — it never fakes a screenshot.
4. The rail, archive row, homepage anchor and `/work/[slug]` case-study page are generated
   automatically.

Case-study sections render only when data exists (`process`, `gallery`, `catalogue` are optional).

### Honesty rules encoded in the data

- `outcomes` are qualitative unless a real measured number exists. Résumé figures (Lighthouse
  68 → 92, 250+ bugs, 12% WAU, 150+ bugs) are quoted exactly where they belong.
- `placeholders` lists field names that still need confirmation; they render with a "to confirm"
  marker rather than as fact.
- `profile.portrait.hasPortrait` is `false` — no photograph was supplied. Drop one at
  `public/work/portrait.jpg` and flip the flag to use it.

### Résumé

`public/Shrey-Patel-Resume.pdf` is generated by `scripts/make-resume.mjs`. Edit the script (or the
content it prints) and run `npm run resume`. Keep the generated PDF in `public/` so the download
link works on static hosting.

## Motion & accessibility notes

- Lenis smooth scroll is driven by GSAP's ticker so ScrollTrigger stays in sync. It is disabled
  entirely for `prefers-reduced-motion`.
- Every reveal is progressive enhancement: markup renders visible, then GSAP animates it. Nothing
  is hidden behind JavaScript.
- The horizontal project rail is pinned only on ≥1024px. On smaller screens it is a native
  snap-scrolling carousel — no scroll hijacking, no horizontal page overflow.
- The hero sculpture falls back to a CSS composition on touch screens, small viewports, reduced
  motion, or when WebGL is unavailable.
- Sound is **off by default**. Nothing is created until the visitor enables it; the audio bed and
  UI ticks are synthesised with the Web Audio API (no audio assets).
- Semantic headings, keyboard-operable tabs and accordions, skip link, visible focus rings.

## Deployment

Any Node/edge host that supports Next.js. Vercel is the simplest: import the repo, set
`NEXT_PUBLIC_SITE_URL`, deploy. No environment variables or external services are required.
